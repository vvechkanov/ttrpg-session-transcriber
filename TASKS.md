## 1. Правила работы

- Каждая подзадача = один логический коммит с работающей сборкой.
- Conventional commits, squash merge запрещён.
- Definition of Done включает документацию: фича не закрыта, пока README / CHANGELOG /
  ARCHITECTURE.md (если затронут) не обновлены.
- Статус фичи правится **в одном месте** — FEATURE_REQUESTS.md. Здесь только ссылка.
- Ступень не объявляется закрытой, пока не выполнен её критерий готовности из VISION.md
  — измерением на реальной сессии, а не ощущением.

### 3.1 Окно таймлайна считается по дефолту, а не по факту (дефект, фича #3)

`ui/models/session.py:1179` зовёт `build_window(max_track_duration=None)` при открытии
сессии, когда длительности дорожек ещё не известны, и берёт дефолтные 4 часа. Когда
`PeaksWorker` приносит настоящие длительности через `SessionMeta.setTotalSeconds`, окно
**не пересчитывается**.

- [ ] Пересчитывать окно по сигналу готовности длительностей и перепубликовывать
      `startPct`/`endPct` рядов
- [ ] Регрессионный тест: окно после `setTotalSeconds` ≠ окно при открытии

Проверено на Сессии 15: бой рисуется на 73.40–91.49 % вместо 69.35–86.44 % — сдвиг ~4 п.п.
для всех полос источников. На `merged.txt` не влияет (мержер выравнивает чат по
`info.txt` независимо от UI-окна) — дефект чисто визуальный.

### 3.2 Линейка в относительных минутах (хвост итерации 3b, фича #3)

`TimelineWindow` уже знает абсолютное окно сессии.

- [ ] Подписи абсолютными часами (18:00, 19:00 …) из `TimelineWindow`
- [ ] Fallback на относительные минуты, когда окна нет (нет `info.txt`, нет чата, нет боя)

### 5.1 Паспорт модуля (принцип П3)

- [ ] Декларативная схема паспорта: нужен ли API-ключ (и чей), покидают ли данные машину
      (какие, куда), требования к железу (RAM / VRAM), языки (где работает, где деградирует),
      понятное человеку описание
- [ ] Паспорт живёт рядом с модулем и читается каталогом, а не редактируется в UI-слое
- [ ] Карточка каталога показывает паспорт **до установки**, крупно

### 5.2 Профиль железа (принцип П4)

- [ ] Снять профиль один раз: CPU, RAM, GPU + VRAM, диск

- [ ] Единственный вопрос, который задаётся человеку, — платить или нет (принцип П2)
- [ ] Дефолт остаётся локальным и проходимым без интернета

### 5.4 Каталог как каталог, а не список из двух

### 5.5 Способность собраться (VISION §6.1)

Не инсталлер как продукт (он на Ступени 5), а **тест**: сборка не должна ломаться молча.
Сейчас `release.yml` собирает exe только по тегу `v*`, тегов в репозитории нет, и
последние правки UI в собранную сборку не попали.

- [ ] CI собирает оба exe на каждый коммит в master и запускает вхолостую (smoke)
- [ ] Первая пересборка после QML-миграции — узнать, что сломалось, пока это вечер работы
- [ ] Артефакты сборки держать скачиваемыми из CI

## 9. Открытые вопросы

1. **WhisperX и число бэкендов.** Июньское решение «трёх хватит, роста не планируем, а
   WhisperX удалить» прямо противоречит ТЗ, где Ступень 1 — это каталог сменных модулей,
   а Ступень 6 — приём чужих. Нужно одно из двух: (а) удаляем WhisperX, каталог начинает
   жить с двух собственных модулей; (б) оставляем и сразу делаем единый реестр (`F-C3`).
   Рекомендация: **(а)** — каталог ценен схемой паспорта и профилем железа, а не числом
   строк в реестре, и мёртвый бэкенд в нём хуже, чем два живых.
2. **`core/cache.py`.** Удалить стаб или дописать? Кэш дорожек уже работает; универсальный
   `DiskCachedSource` понадобится только под `DiskCachedMerger` на Ступени 4.
   Рекомендация: **удалить** сейчас, вернуть в §6/Ступень 4, если понадобится.
3. **Ступень 0 — объявляем закрытой?** Критерий ТЗ выполнен и измерен (§3). Формально
   осталось решение владельца: закрываем и переходим к каркасу и каталогу, или сначала
   добиваем хвост §3.1–§3.7.
4. **Форма акустического признака** (`F-8/1`). Предложение ревью:
   `AcousticFeatures(start, end, speaker, values: dict[str, float], reliability: dict[str, str])`
   как новый тип аннотации, отдельный поток в `Timeline`, поле `features` на `SpeechEvent`;
   существующий `EmotionTag`/`emotion: str` остаётся для меток уровня 3–4 и никогда не
   используется для измерений. Решить сейчас — реализовать на Ступени 3.
5. **Как акустический модуль получает границы реплик** (`F-8/2`). Три варианта: (а) свой
   VAD и проекция по пересечению — тогда из ТЗ надо вычеркнуть «едет на ASR-проходе
   бесплатно»; (б) новый контракт `TrackAnalyzer(audio_path, segments)` рядом с
   `transcribe_track`; (в) хук внутри речевого прохода. Рекомендация ревью — **(б)**.
6. Вопросы самого ТЗ (имя продукта, микроопрос на выдаче, атрибуция, безопасность
   стороннего кода, где живёт каталог, деньги) живут в VISION.md §9 и сюда не дублируются.
